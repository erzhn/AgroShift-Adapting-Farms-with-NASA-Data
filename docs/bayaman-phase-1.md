# Баяман — первый этап

Реализованы первые **4 из 7** пунктов личного чек-листа из «AgroShift — распределение
задач на хакатон2»: общие контракты, справочник пяти культур, демо-хозяйство и пять
сценариев. Это первая половина с округлением вверх по числу пунктов, не оценка трудозатрат.

| Пункт | Результат |
|---|---|
| 1. Farm, Field, Crop, Scenario; get_farm, get_crop | Типизированные Pydantic DTO и работающие функции чтения PostgreSQL |
| 2. Пять культур с источниками чисел | Люцерна, кукуруза на силос, яровая пшеница, сухая фасоль, яблоня; варианты, цены и месячные затраты |
| 3. Демо-хозяйство «Асан» | 3 контура по 2 га, яблоневый сад, люцерна, силосная кукуруза, 8 молочных коров, очередь, деньги |
| 4. Пять сценариев | Исторический 2023 год, малоснежная зима, вода −20% в июле–августе, корм +40%, оплата +60 дней |
| 5. CRUD и справочники через HTTP | Следующий этап; существующие эндпоинты пока отвечают 501 |
| 6. Главный экран | Следующий этап: MapLibre, месяцы, слоты WaterLane/MoneyLane, переключатель стратегии |
| 7. Форма профиля | Следующий этап |

Распределение задач описывает SQLModel/SQLite, но готовый репозиторий уже использует
SQLAlchemy/PostgreSQL/PostGIS. Сохранён существующий стек. Общие контракты находятся
в `backend/app/modules/farms/schemas.py`, как предусмотрено распределением.
HTTP-роутеры, расчётные модули других участников и оболочка фронтенда не менялись.

## Запуск

Из корня репозитория:

```sh
docker compose up -d db api
docker compose exec -T api alembic upgrade head
docker compose exec -T api python -m scripts.seed --check
docker compose exec -T api python -m scripts.seed
```

Если локальный образ ещё не собран, первая команда: `docker compose up -d --build db api`.
При обычном запуске контейнера миграции также применяются автоматически.

`--check` валидирует данные без соединения с БД. Основная команда загружает данные
одной транзакцией и печатает ID и число вставленных строк. Повторный запуск
возвращает нули: существующие записи, включая пользовательские исправления, сохраняются.
Совпадение уникального кода с посторонней записью отменяет весь seed; принудительной
перезаписи нет. Изменение JSON само по себе не обновляет уже загруженную запись.

Источник чисел: `backend/data/seed/farms.json`. Seed офлайн; загрузка NASA принадлежит
модулю воды. Плановый сезон фиксирован — **2027**, дата подготовки оценок — **2026-11-15**.

Демо-хозяйство: `84e256d0-16b1-59a5-85a8-f41ed10410a8`.
Остальные ID воспроизводимо вычисляются через `seed_id(...)` и печатаются загрузчиком.

## Внутренние контракты

Из `backend/` или внутри контейнера API:

```python
from app.modules.farms.demo import FARM_ID, seed_id
from app.modules.farms.service import get_crop, get_farm, list_scenario_presets

farm = get_farm(FARM_ID)
crop = get_crop(seed_id("crop/maize"))
presets = list_scenario_presets()

assert farm.area_ha == 6
assert crop.variants[0].product == "silage"
print(farm.model_dump_json(indent=2))
```

Функции принимают UUID или его строковое представление. Неизвестный ID вызывает
`NotFoundError`, который существующий обработчик API преобразует в RFC 9457 / 404.
Неявной подмены отсутствующей записи демо-данными нет. При необходимости можно
передать `session=db` как именованный аргумент; функции не коммитят и не закрывают
сессию вызывающего кода. Без него сессия открывается и закрывается самой функцией.
Результат — самостоятельный DTO, без ленивых ORM-связей.

| Данные | Где читать и как интерпретировать |
|---|---|
| Культура на поле | `field.seasons`: `crop_id`, `crop_variant_id`, `year`, сроки и урожайность |
| Kc и Ky | `crop.kc_ini/mid/end`, `stage_days[4]`, `root_depth_m`, `p_depletion`, `ky` |
| Урожайность | `crop.variants[].yield_potential_t_ha`; всегда смотреть `product` |
| Цена | `crop.price.price_som`, `unit="t"`; только общий справочник Чуйской области, не частные цены |
| Затраты | `crop.variants[].costs[]`: `operation`, `month` (1–12), `cost_som_ha`, `labour_h_ha` |
| Деньги | `farm.cash_accounts`, сумма `cash_som`; `family_reserve_som` — семейные расходы в месяц |
| Очередь | `farm.water_rights`: `turn_interval_days`, `turn_hours`, `flow_l_s`, `failure_months` |
| Сезонный лимит | `limit_m3` / `limit_hours`; `limit_hours` не длительность одной очереди |
| Геометрия | GeoJSON Polygon/Point, порядок координат долгота–широта, EPSG:4326 |
| Происхождение | `provenance[имя_входа]`: тип источника, уверенность, пояснение, ссылка и дата |

Вода: мм и м³, 1 мм × 1 га = 10 м³. В демо лимит и расход измеряются на
водовыпуске хозяйства. При 60 л/с и 8 часах очередь даёт 1 728 м³ **брутто**;
это ещё не вода в корневой зоне. Полив, КПД и нетто считает модуль воды.
Минимальная запись канала нужна только для ссылочной целостности Асана. Seed
20 хозяйств, график подачи и координация канала остаются задачей Жаныбека.

Сад привязан к своему полю и не добавляет ещё 2 га к сумме площадей. Контуры
синтетические, расположены рядом с Сокулуком; это не кадастровые границы.
У многолетников `sowing_date` в демо обозначает начало моделируемой вегетации,
а год посадки сада хранится отдельно. Люцерна использует усреднённые за сезон Kc,
без моделирования отдельных укосов; `harvest_date` — конец демонстрационного сезона.

## Источники и неизвестные значения

- [FAO-56, глава 6, таблицы 11–12](https://www.fao.org/4/x0490e/x0490e0b.htm):
  Kc, высота растений, длительности стадий яровой пшеницы и фасоли.
- [FAO-56, глава 8, таблицы 22 и 24](https://www.fao.org/4/x0490e/x0490e0e.htm):
  диапазоны корней, p и сезонные Ky из FAO-33.

Выбранные глубины корней лежат в справочных диапазонах и не являются измерением
на поле. Местные стадии люцерны, силосной кукурузы и яблони, базовые температуры,
урожайность, цены, затраты и финансовые параметры явно отмечены как оценки.
Ky яблони = 1 также отмечен как оценка: в таблице 24 яблони нет.

`ky_stages`, температурные пороги повреждения, `gdd_required` и высота полей оставлены
неизвестными, если нет проверенного значения. Сезонный Ky нельзя без обоснования
копировать в каждую стадию. Отсутствующая цена или баланс счёта остаётся `None`;
`completeness="partial"` и `unknown_inputs` показывают неполноту. Неизвестная высота
поля должна быть заполнена модулем данных до расчёта ET0 по высоте.

Сценарий `like_2023` выбирает реальный исторический год, без дополнительного
искусственного нагрева; его использование требует снимка POWER от Ислама.
`low_snow` — оценочный стресс подачи, не спутниковая модель снега. `water_supply_months`
ограничивает изменение воды выбранными месяцами, `None` означает весь сезон.
`price_factors["feed"]` меняет только корм, не все цены. У `payment_delay_days` единица — дни.
Исполнение сценариев — ответственность расчётных модулей.

## Проверки

```sh
docker compose exec -T api ruff check .
docker compose exec -T api pytest -q
docker compose exec -T -e AGROSHIFT_TEST_DB=1 api pytest -q
```

Обычный `pytest` выполняет автономные тесты; тесты с маркером `db` требуют явного
`AGROSHIFT_TEST_DB=1`. Они создают отдельную случайную схему внутри транзакции,
проверяют реальный PostGIS и откатывают и таблицы, и данные. Рабочие таблицы не очищаются.

Проверяются коэффициенты, единицы, границы ввода, целые сомы, полнота источников,
детерминированность ID, связи культур и полей, площади геодезическим расчётом,
отсутствие пересечений, сериализация DTO, пять сценариев, повторный seed,
сохранение правок и полный откат при конфликте. Существующие health-тесты включены.

Результат проверки 15 ноября 2026: **60 тестов прошли** (48 автономных, включая
2 исходных health-теста, и 12 интеграционных). `ruff check .` прошёл;
`alembic check` не обнаружил расхождений между ORM и миграциями. Seed загружен в
локальную БД, повторный запуск вставил 0 строк. Обычные вызовы `get_farm` и
`get_crop` без переданной сессии работают. `/health`, `/health/db` и `/openapi.json`
вернули HTTP 200. В тестах остаётся исходное предупреждение Starlette о deprecated
адаптере httpx; оно присутствовало до изменений и не вызывает падения тестов.

Перед следующим этапом следует согласовать эти контракты с владельцами расчётных
модулей. Результат этапа не означает готовность всего MVP: HTTP CRUD и фронтенд
сознательно оставлены в оставшейся части задач Баямана.
